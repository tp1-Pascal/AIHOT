## 2. 产品与架构地图

流程：信源 → 判重/正文抽取 → 预筛/两次评分/写作 → 事件归组 → 公开读取层 → 网页/RSS/API/MCP/报告。

- `apps/api/`：Fastify，后台、网站接口、公开 API、RSS、MCP。
- `apps/web/`：React Router 服务端渲染，只通过 HTTP 读 API，不直连数据库。
- `apps/worker/`：pg-boss 定时与队列，采集、模型分析、归组、报告等。
- `packages/backend/src/sources/`：采集器与调度。
- `content/`：入库、去重、正文。
- `editorial/`：分析流程、提示词、模型选择。
- `events/`：事件归组与热度。
- `publication/`：所有公开出口统一读层，公开条件集中在 `scope.ts`。
- `providers/`：付费服务、回执和预算。
- `industry/`：信源、分类、提示词、筛选标准。
- `site/`：品牌、文案、模型默认值与出刊设置。

重要规则（D）：打开页面不调用模型；页面读已有结果。已有资料入库不等于符合公开条件。未知发布日期、历史回灌及全文许可各有独立约束。不得为了首页有内容伪造分析结果或强制精选。

## 3. 原生信源与 X 的真实实现

### 六类信源（D）

- RSS：普通 RSS/Atom，无模型或付费采集 key 的必需依赖。
- web_list：HTML 选择器；普通模式不执行 JavaScript。Jina 为可选付费路径。
- json_list：字段映射，带凭据接口只允许同源重定向。
- x_search：SocialData 搜索，需要 `SOCIALDATA_API_KEY`。
- mp_account：公众号 Dajiala，需要相应 key。
- external：外部脚本 POST `/api/ingest/items`，需要 `INGEST_TOKEN`。

### X 采集器（S）

`fetchXSearch` → `readXSearch` → `searchTweets` → `GET https://api.socialdata.tools/twitter/search`。

- 使用服务 Bearer key，不读取用户浏览器 Cookie。
- 常见配置：`from:SomeAccount -filter:replies`，`searchType: Latest`。
- 提取主帖 ID、作者、正文、媒体、引用帖；候选身份为 `x:<tweetId>`。
- 按 `since_id` 增量、cursor 分页，保留未读区段；新帖最多 10 页、补积压最多 10 页，最多 5 个积压区段。过期 cursor 或积压溢出可能丢段，代码会计数，不能承诺全量无遗漏。
- 首次无水位仅读一页；原生逻辑过滤 `retweeted_status`，因此不等于完整复制 Following 页面。
- 符合条件的普通账号最多 24 个一组，并受查询长度约束，合并请求省费用。
- 半小时回执窗口复用已获取结果；付费请求经过预算与回执。
- provider 的成本估算按返回对象数计算。文件注释与文档存在“按请求”的简化措辞，不应据此报价；当前实际价格需向供应商查证。

现有实现没有证明能读取本人书签、喜欢、浏览历史或精确个人 Following。监控一组公开作者不等于读取本人时间线。

## 4. X 获取方式的决策边界

### A. orVPS 固定代码 + 数据接口

优点：不依赖 Mac 开机/浏览器 UI，不需要每帖调用模型。原生 SocialData 路线复用最多。
代价：服务 key、数据费用、供应商可用性。不是免费，也不自动拥有私有账户数据权限。

### B. 官方 X 用户授权接口

[时间线文档](https://docs.x.com/x-api/posts/timelines/introduction)描述用户授权的倒序 home timeline；[书签文档](https://docs.x.com/x-api/posts/bookmarks/introduction)描述已认证用户书签。

2026-10-21 查阅时，home timeline 文档要求 OAuth 用户上下文，给出最近 3,200 条或 7 天范围。应在真正接入前重核账户权限、价格和限制。授权有效时服务器可运行，不需要网页一直开着。尚未生成授权、配置 token 或实测。

### C. Grok / Grok Bot

[官方 X Search](https://docs.x.ai/developers/tools/x-search)提供公开搜索、用户搜索、线程读取。API 有模型 token 与搜索工具数据费用，不是“消耗一点 token 就拿到所有个人数据”。

Mac 只读回执：Grok Bot.app 0.72.1 的 XSearchArgs 发现查询、日期、作者过滤；未找到本人历史/Following 参数。此为本地可见接口证据，不代表对整个产品做了完整能力否定。

Grok Bot 订阅是否提供稳定的固定程序调用入口、是否有结构化原文输出、自动调用条款/额度与成本：**unknown，下一步与 Bot 对接核实**。不能把 xAI API 定价直接当作 Bot 订阅计费，也不能提取订阅凭据充当 API key。

### D. Mac 浏览器

已登录页面可做小样本读取，但依赖在线机器、会话有效、页面结构、可用执行入口；不能保证所有历史帖。云端助手适合开发核验，不作为用户长期服务依赖。迁移浏览器到 orVPS 仍有会话维护和资源成本。

目前该路线只做了小样本核验，没有完成刷新、滚动、断点恢复、定时运行。

## 5. 分类与个人数据边界

- 来源分类（Following/书签/喜欢/RSS）由确定性来源元数据产生，不让模型猜。
- 内容分类可先规则/作者名单/关键词，少量不确定项再批量模型判断；这是待验证方案，不是现成落地结果。
- 原生行业分类与精选逻辑应先复用，不能另建一套与公开条件冲突的旁路。
- external 接口最多 50 条/批；新 source 默认 isolated，不自动公开（D）。
- **isolated 不等于独立私有资料库**：此前代码分析回执指出既有源复用和全局材料身份可能跨来源共享。个人时间线接入前，必须以合成数据验证与公开源碰撞时的边界，不能只看默认 isolated 就宣称隐私隔离完成。
- 不保存账号 Cookie、密码或 token 到知识库；不上传真实时间线全文；不自动向外发布用户的书签/喜欢关系。

## 8. 低资源、低费用注意点

- 不在 orVPS 运行本地大模型；采集代码与模型分析分开算成本。
- 先前源码分析：worker 包含多种定时任务；直接全量启动并不等于低频 RSS。
- 模型开关关闭不代表分析任务自动暂停；若启动 worker，可能认领后失败重试。上线前需复核实际队列行为。
- 单次 collect 脚本存在强制采集路径，可越过 enabled/下次抓取时间；不能依赖全局开关证明一次手动调用不会发外部请求。
- 自动频率调整可能把手设低频改回更高频率，需核对任务再启用。
- GPT 订阅不是 AIHOT 的 OpenAI-compatible API key；当前没有订阅分析结果回写闭环，不能声称免费自动替代。
- 默认完整分析多步骤，不能用“每帖只一次调用”估算费用。必要时先限制候选量、去重，再实测。
- 保留上游许可和署名；MIT 不包含 AIHOT 名称/Logo，实际品牌仍需替换。
