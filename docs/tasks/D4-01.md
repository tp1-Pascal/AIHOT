## Implementation and synthetic database boundary

- The existing bearer-protected HTTP route delegates to receiver validation in `ingest/items.ts`; private mode rejects non-exact IDs and any unknown/disabled/non-external/non-isolated source before changing health, discoveries, materials, jobs or ingest events. Source selection is locked through the batch transaction.
- `private-ingest:` is a reserved stored identity prefix. Configured private sources share this namespace; public sources retain their previous keys. Private revisions, aliases, concurrent inserts, cross-private discoveries and reused external IDs still deduplicate within the private domain. Public reuse of a private key is rejected.
- Both first insert and repeated discovery reconciliation stop on the stored private boundary. The publication layer treats these rows as isolated regardless of later source-mode edits, ingress-config removal or explicit public/selected editorial overrides. Withdrawn publication records may exist for private rows; public detail, lists, feeds and selected ledger exclude them. This does not claim that raw was previously exposed directly by the v1 payload.
- No schema migration, historical backfill, deletion, real-source collection, live model/X/SSH call, upstream write, token/key generation, permission change, merge or deployment was performed.

PG installation: lockfile `npm ci --ignore-scripts`; Debian official HTTPS package index plus `postgresql-17`, `postgresql-client-17`, `libpq5` 17.11 packages, checked against index SHA256 and unpacked only under `/tmp/d4-01-pg-dist` (no package scripts/system service changes). The initial apt snapshot index was unavailable; its errors are retained.

## Deployment prerequisites (not applied)

Provision the chosen source IDs as enabled `kind=external`, `participation_mode=isolated`; set non-secret `INGEST_PRIVATE_SOURCE_IDS=private-x-example,private-x-secondary-example` on the API and every backend process that writes material. Use the same fixed IDs/config across those processes. IDs accept 1–120 ASCII letters/digits/dot/underscore/colon/hyphen, starting with a letter/digit. Request IDs match exactly; whitespace or truncation is never accepted in private mode. Absent setting deliberately preserves the existing public ingest product; present empty/malformed setting denies all ingest sources. Configure no actual credentials from this PR. The existing ingest authentication remains required.

This protects newly accepted private material; it does not relabel or clean up legacy material that predates the boundary. Operators must assess historical data separately before any real rollout. Stored private identities stay nonpublic even if ingress config is later removed; removal restores legacy behavior for future unmarked ingest, so keep the restriction enabled while accepting private X reports. No live rollout was performed.
